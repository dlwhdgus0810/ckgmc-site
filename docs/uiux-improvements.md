## 검증 방법

Node 22.12 이상에서 `npm ci` 후 `npm run check`, `npm run build`를 실행한다.

공개 화면 회귀 검사는 로컬 서버가 켜진 상태에서 실행한다.

```sh
npx playwright install chromium
npm run dev
# 별도 터미널
npm run test:ui
```

기존 Chromium을 사용하려면 `CHROMIUM_PATH=/usr/bin/chromium npm run test:ui`로 실행한다. 주소는 `BASE_URL`로 지정하며 기본값은 `http://localhost:4321`이다. 검사 스크립트는 외부 요청을 차단하고 폼 전송 성공·실패를 모의 처리한다. 실제 문의나 세례 신청을 보내지 않는다.

관리자 편집 회귀 검사는 로컬 D1 마이그레이션과 개발 로그인을 준비한 뒤 `npm run test:editor`로 실행한다. 기본 개발 계정은 `admin@example.com`이며 `TEST_ADMIN_EMAIL`로 지정할 수 있다. 이 검사는 로컬 호스트에서만 실행되며 콘텐츠 변경 요청을 차단하고 미게시 입력·미리보기·복구·순서 변경·모바일 배치를 확인한다.

추가 검증은 로컬 D1에 사용자별 보고서 35건과 답글을 넣어 전체 개수·페이지 이동·기간 검색·확인 상태·폼 오류·임시복구를 확인했다. 관리자 6개 화면을 1366/390/320px에서 확인했고, 그룹 생성·수정 오류에서 DB 변경 없이 입력 보존을 검증했다. 테스트 데이터는 검증 후 제거했다.

## 운영상 구분

- 관리·보고서 임시 입력은 현재 탭의 sessionStorage에 보관하며 24시간 이내 입력을 복구 대상으로 제안한다. 공개 문의·세례 폼은 사용자가 임시 저장을 누르면 해당 탭에 보관한다. 탭을 닫거나 브라우저 저장소를 지우면 복구할 수 없다. 파일은 다시 선택해야 한다.
- 답변 확인 기록은 사용자별 브라우저 저장소의 보고서/답변 ID만 사용한다. 다른 기기와 동기화되지 않는다는 안내를 화면에 표시한다.
- 일정이 확정되지 않은 모임에는 현재 시간·장소를 지어내지 않고 담당자 확인 경로를 제공한다. 응답 기한도 임의로 약속하지 않는다.
- PDF 쪽수나 없는 본문 요약을 생성하지 않는다. 파일 크기는 같은 출처의 실제 응답으로 확인하고, 가능한 본문·기존 요약을 보여준다.
- 미리보기는 현재 입력 확인용이며 실제 게시 화면과 배치가 다를 수 있다. 저장하고 게시하면 기존 GitHub/Cloudflare 배포 흐름을 사용한다.
- 반응형 이미지는 빌드 결과물이며 Git에 추가하지 않는다. 파일 내용 해시로 캐시하고 깨끗한 빌드에서도 자동 생성한다.
